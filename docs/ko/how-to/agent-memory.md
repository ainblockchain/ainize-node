# 에이전트에 기억 붙이기

`ainize-agent run` 은 지식 하나를 사고, 그것이 모델의 답을 바꿨다는 것을 증명하고, 끝납니다. 내일 다시 실행하면 다시 아무것도
없는 상태에서 시작합니다 — 무엇을 샀는지, 무엇을 조회했는지, 무엇에 이미 답했는지 모릅니다.

`ainize-agent ask` 는 기억을 가진 같은 에이전트이고, 그 기억이 전부입니다. 질문이 들어오면:

```
이미 가지고 있는 기억으로 답할 수 있나?      가능 → 답한다. 조회도, 모델 호출도, 비용도 없다.
이 질문을 담은 LISTED 지식이 있나?           있음 → 산다. 적용한다. 그대로 둔다.
그것도 아니면                                업스트림에 묻는다. 물어볼 때마다 매번 조회 비용이 든다.
    …그리고 같은 SHAPE 을 충분히 여러 번
      조회해서, 조회 비용이 이미 한 번
      컴파일하는 비용을 넘어섰다면            → ainize 한다: 조회해 둔 것으로 학습 데이터를 만들고,
                                               레슨 하나를 써서, 결과 엔그램을 자기 기억에 넣는다.
```

조회는 **질문마다** 내는 비용입니다. 컴파일된 기억은 **한 번만** 내는 비용입니다. 이 문서는 그 둘 사이를 판단하는 물건을
어떻게 돌리는지, 그리고 그것이 무엇을 거부하는지에 대한 것입니다.

## 시작하기 전에 — 무엇을 쓰는가

`ask` 는 서로 환산되지 않는 네 가지를 씁니다. 그리고 한도가 없으면 그중 **아무것도** 쓰지 않습니다.

| 단위 | 옵션 | 무엇을 사는가 |
|---|---|---|
| 돈 | `--budget-per-day` | 마켓의 지식 |
| 업스트림 조회 | `--queries-per-day` | 남의 MCP 서버 호출 1회 |
| 레슨 | `--lessons-per-day` | 학습 작업 1건 — 노드는 제출 시점에 차감하고 환불하지 않습니다 |
| GPU 초 | `--gpu-seconds-per-day` | 트레이너의 시간 |

한도가 없다는 것은 "무제한" 이 아니라 **이 에이전트가 그 단위를 스스로 쓰지 않는다**는 뜻이고, 한도를 정할 옵션 이름까지
말해 줍니다. **한도는 이 루프 바깥에서만 정할 수 있습니다** — 옵션, `NGRAM_AGENT_*` 환경변수, 또는 `<home>/agent.json` 의
`budget.*` 항목. 플랜 파일도, 마켓의 응답도, 402 응답도 한도를 올릴 수 없습니다. 무인으로 켜 두어도 되는 이유가 이것입니다.

```bash
ainize-agent budget                       # 네 단위 전부, 남은 양, 그리고 각 한도의 출처
```

이 화면의 모든 숫자는 `<home>/spend.jsonl` 과 `<home>/purchases.jsonl` 에서 읽은 것입니다.

## 1. 물어보기

```bash
ainize-agent ask "USDC 컨트랙트 주소 알려줘" \
  --market http://localhost:3402 --queries-per-day 20
```

처음에는 기억에 아무것도 없고, 그 마켓에 이 질문을 담은 지식도 없고, 표현에 맞는 **플랜**이 있으므로 — 에이전트는 업스트림
서버를 한 번 호출하고, 받아온 행으로 답합니다. 그 행들은 이제 기억에 있습니다.

같은 질문을 다시 하면 비용이 전혀 들지 않습니다. 조회도, 모델 호출도 없습니다.

```bash
ainize-agent ask "USDC 컨트랙트 주소 알려줘" --json | jq '.via, .cost'
# "memory"
# { "completions": 0, "queries": 0, "money": null, "lessons": 0, "gpu_s": null, "ms": 82 }
```

### 모델을 두 번 묻지 않고 판단하는 방법

이 판단에는 **모델 호출이 0회** 듭니다. 모델에게 "이거 아니?" 라고 묻지 않습니다. 인덱스에게 묻습니다.

1. 질문을 노드 자신의 프롬프트 키로 정규화합니다. 학습 데이터에서 배운 사실과 사람이 타이핑한 질문이 같은 키에 떨어지도록;
2. `<home>/memory-index.json` 에서 찾습니다;
3. 모델에 올라가 있는지는 **스택 지문**으로 확인합니다 — 공개 엔드포인트 `GET /api/runtime` 이 알려주는
   `sha256(모델 + 각 레이어의 위치·id·해시)`. 무엇이든 적용·제거·재정렬·교체되면 바뀝니다. 이 에이전트가 했든, 같은 공유
   모델의 다른 사용자가 했든;
4. 그 지문에 대한 답 캐시가 살아 있으면 기억한 답을 그대로 돌려줍니다. 아니면 모델을 **한 번** 호출해서 기억한 답과
   대조합니다 — 그 한 번의 호출이 검증이자 곧 답입니다. 불일치는 오류가 아니라 그 행을 강등하고 비용 경로로 넘어가는
   신호입니다. **기억은 주장이고, 모델이 사실입니다.**

서빙 모델이 없으면 기억한 답이 `via: "memory"` 라벨과 함께 나옵니다. 그 라벨은 항상 답과 같이 다닙니다.

## 2. 플랜 — 무엇을 조회하고 무엇을 조회하지 않는가

**플랜**은 `<home>/plans/*.json` 에 있는 선언적 JSON입니다: 서버, 도구, 인자, 응답을 행으로 바꾸는 방법, 그리고 알아들을
표현들 — 영어와 한국어를 같은 목록에 씁니다.

```bash
ainize-agent plans --check
```

`--check` 는 플랜이 조회 비용을 쓰기 전에 돌려 볼 값어치가 있습니다. 가장 중요한 항목은 **슬롯을 채우면 shape 이 바뀌는가**
입니다. 바뀐다면 개체마다 카운터가 따로 생기고, 에이전트는 자기가 같은 것을 반복하고 있다는 사실을 영원히 알아채지 못합니다.

어떤 패턴에도 맞지 않는 질문은 **조회하지 않습니다**. 남의 API 키로 질의를 추측하는 대신, 가진 플랜을 출력하고 멈춥니다.
이 방식에 대한 정직한 설명은 이렇습니다: 이것은 *미리 적어 둔* 표현들을 묶을 뿐, 뜻을 이해하지는 않습니다.

## 3. 무엇을 "같은 것을 또 조회했다" 로 세는가

질문이 아니라 **조회**를 셉니다. 에이전트는 두 문장이 같은 뜻인지 신뢰할 만하게 판단할 수 없고, 그런 척도 하지 않습니다.
대신 같은 서버의 같은 질의를 인자만 바꿔 실행했다는 것은 **정확히** 압니다.

```
shape = sha256({ server, tool, skeleton(arguments), mapping.path, mapping.prompt, mapping.answer })
```

`skeleton()` 은 모든 리터럴을 타입 자리표시자로 바꾸고, GraphQL 문서는 구조만 남깁니다. 그래서 한 호출의 `"USDC"` 와 다음
호출의 `"WETH"` 는 **하나의** shape 이 됩니다 — 질문 문자열로 세는 카운터가 절대 발화하지 못하는 바로 그 지점입니다.

```bash
ainize-agent memory
#   ef393190fa86  조회 12회 · 사실 10개 · 신규 10 · 재조회 2 · 변동 0 · 측정 조회 12 / 회상 0 / 학습 1
```

카운터 셋과 신호 하나: `refetched` (표현이 어떻든 이 에이전트가 같은 사실에 두 번 돈을 낸 증거) 와 `churned` (두 번의 조회
사이에 답이 **바뀐** 사실 — 그런 것은 컴파일하지 말고 업스트림에 두어야 합니다).

## 4. 언제 컴파일하고, 언제 거부하는가

네 개의 관문을 전부 통과해야 합니다.

| 관문 | 조건 |
|---|---|
| 경제성 | 조회 횟수 ≥ N\* |
| 재료 | 서로 다른 사실 8개 이상 — 노드 자신의 `teach.rowsPerJob.floorGradient` |
| 안정성 | 변동률 ≤ `--max-churn` (기본값: 전혀 허용하지 않음) |
| 예산 | 레슨 1개 **와** GPU 초가 오늘 남은 양에 둘 다 들어갈 것 |

**N\* 는 누가 고른 숫자가 아닙니다.** 계산식은 `graph/bench` 의 것이고 —

```
N* = 일회성 비용 / (질문당 조회 비용 − 질문당 회상 비용)
```

— 그 실행 `r1` 은 양쪽 arm 을 모두 채점하고 가격을 매겨야 한다는 이유로 이 값을 **계산하지 않은 채로** 문서에 남겨 두었습니다.
그래서 에이전트는 자기가 기록한 측정값으로 단위별로 계산하고, 그중 가장 큰 값을 씁니다.

- **초** 가 실제 손익분기점이고, 판단을 좌우하는 값입니다;
- **조회 횟수** 는 사실이라서 보고하지만 (학습은 업스트림을 호출하지 않으므로 컴파일은 즉시 이득) 판단을 좌우하지 않습니다;
- **토큰** 은 손익분기점 자체가 없습니다 — 조회는 모델 토큰을 쓰지 않고 회상은 씁니다 — 그래서 조용히 세지 않고, 보고한 뒤
  최댓값에서 제외합니다.

어느 한쪽이든 측정이 3건 미만이면 N\* 는 정의되지 않고 에이전트는 학습하지 않습니다. 노드 자신의 `ETA_MIN_SAMPLES` 규칙입니다:
stub 작업 3건이 추정치가 되어서는 안 되고, 조회 3회가 손익분기점이 되어서도 안 됩니다.

```bash
ainize-agent memory --why ef393190fa86
# would it be compiled? no
#   no  economic   {"lookups":10,"n_star":null,"binding_unit":null,"declared_floor":null,"computable":"no"}
#   ok  material   {"distinct_rows":10,"floor":8}
#   ok  stability  {"churn_rate":null,"churned":0,"refetched":0,"max_churn":0}
#   no  budget     {"lessons":1,"gpu_s":0,"checked":2}
#   missing: bake_cost: no lesson of this shape has finished on a real trainer
```

**따라서 첫 학습은 언제나 소유자의 결정입니다.** `bake_cost` 는 이미 끝난 레슨에서만 측정할 수 있고,
`NGRAM_TEACH_BACKEND=stub` 으로 돌린 레슨은 고정 샘플 파일을 복사할 뿐이라 그 초는 파일 복사 비용이므로 의도적으로 가격으로
세지 않습니다. 켜는 방법은 둘 중 하나입니다.

```bash
# 선언된 정책 — 나타나는 모든 곳에서 정책이라고 표시되며, 측정값으로 제시되지 않습니다
ainize-agent ask "…" --bake-after 3 --lessons-per-day 1 --gpu-seconds-per-day 3600

# 또는 레슨 예산을 주고 직접 측정하게 두면, 가장 이른 자율 학습은 그 shape 의 4번째 조회입니다
```

## 5. 학습이 하는 일과, 일부러 하지 않는 일

이 에이전트가 **이미 값을 치른** 행들(`<home>/retrieved/<shape>.jsonl`, 봉인된 프로버넌스가 옆에 있습니다)로 학습 데이터를
만들고, 업로드하고, 레슨 하나를 제출하고, 노드 자신의 상태 기계를 폴링하고, `bake` 이벤트를 **제출 시점과 종료 시점 두 번**
기억에 씁니다 — 학습 도중에 죽어도 작업 핸들은 남도록.

**공개하지 않습니다.** 공개는 누구도 되돌릴 수 없는 앵커를 남기고, 사용한 행들은 게이트웨이 키를 통해 받은 남의 데이터입니다.
누가 그 위에 만들 수 있고 누구에게 얼마가 가는지는 에이전트가 아니라 소유자가 정합니다. 실행은 그 명령 한 줄을 알려주며 끝납니다.

```bash
ainize teach publish <레슨 id> --name "…" --price 2 --consent-permanent --consent-rights
```

무엇을 쓰기 전에 반드시 소리 내어 말하는 것이 둘 있습니다.

- **레슨은 이 에이전트 자신의 신원으로 서명됩니다** — 구매 대금을 내는 키와 같은 키입니다. 학습한 것과 구매한 것이 공개
  기록에서 하나의 주소로 묶입니다. 이는 의도된 것이고(계보에 필요합니다), 첫 레슨 전에 알고 있어야 합니다.
- **`NGRAM_TEACH_BACKEND=stub`** 에서는 레슨 기록과 데이터셋, 상태 전이는 실제이고 결과 파일은 가중치를 학습하지 않은 고정
  샘플입니다. stub 실행에서 나온 값은 모델에 대해 아무것도 말해 주지 않습니다.

## 6. 기억과 노드가 어긋날 때

`ask` 는 매 실행 시작에 노드의 공개 엔드포인트 `GET /api/runtime` 을 읽고 대조합니다. 규칙은 한 문장입니다:
**모델에 대해서는 노드가 옳고, 자기 자신에 대해서는 에이전트가 옳으며, 어긋남은 조용히 해소하지 않고 기록합니다.**

| 무슨 일이 있었나 | 에이전트가 하는 일 |
|---|---|
| 기억은 올라가 있다는데 노드 목록에 없음 | 모델에는 없습니다 — 보유(`held`)로 낮추고, 회상이 모델을 안다고 주장하지 못하게 합니다 |
| 노드 목록에 이 에이전트 것이 아닌 레이어가 있음 | 외부 레이어입니다: 지문에는 반영되고, 이 에이전트의 기억이 되지는 않으며, 절대 제거하지 않습니다 |
| 같은 지식인데 본문 해시가 다름 | 본문이 밑에서 바뀐 것입니다 — 그 지식에서 온 모든 사실을 `unverified` 로 낮춥니다 |
| 에이전트 홈이 사라짐 | 기억이 비었다고 말합니다. 적재 상태·소유권·수록 범위는 복구하지만 조회 이력은 복구하지 않으므로, 카운터는 0부터 다시 시작하고 없는 기억 위에서 학습하지 않습니다 |

## 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 답했음 |
| 1 | 답하지 못함 |
| 2 | 예산이 거부했고, 아무것도 쓰지 않았음 |

무인 루프는 "감당할 수 없었다" 와 "고장 났다" 를 구분할 수 있어야 합니다.

## 무엇이 어디에 있는가

```
<home>/memory.jsonl          추가 전용: learn, recall, retrieve, buy, apply, bake, demote, conflict
<home>/memory-index.json     파생 스냅샷. 지우면 재생 비용이 들 뿐 사실은 잃지 않습니다
<home>/spend.jsonl           예약과 정산마다 한 줄씩. 의도를 먼저 씁니다
<home>/retrieved/<shape>.*   학습이 쓰는 행들과 봉인된 프로버넌스
<home>/plans/*.json          이 에이전트가 조회할 줄 아는 것
<home>/agent.json            옵션을 매번 쓰기 싫을 때의 한도 설정
```

전부 텍스트입니다. `cat`, `grep`, `diff` 가 그대로 동작하고, 디렉터리를 다른 기계로 복사하면 기억도 같이 옮겨집니다.
