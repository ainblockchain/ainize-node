# 남의 지식 위에 얹어 만들기

이 네트워크의 모든 지식은 다음 지식의 바닥이 될 수 있습니다. 공개된 지식이 배운 질문을 가져와, 그것이 틀리거나
다루지 않는 질문을 더하고, **그 위에** 훈련해서 공개합니다. 공개 기록에는 무엇 위에 만들었는지가 남고, 내 지식을
사는 사람은 그 기반도 함께 필요하다는 사실을 안내받으며, 기반을 만든 사람은 내 지식이 팔리는 동안 매 판매의 일정
몫을 받습니다.

이 문서는 터미널에서 밟는 전체 경로입니다. 브라우저에서는 `<node>/teach/upload?on=<id>`가 같은 일을 합니다.

## 시작하기 전에

**내 노드가 판매자와 같은 원장을 읽어야 합니다.** `--ledger local`로 만든 노드는 자기만의 기록 DAG를 갖기 때문에,
AIN 체인에 공개된 지식은 피어가 아무리 건강해 보여도 영원히 보이지 않습니다. `ainize peers ls`가 이 불일치를
표시하고 `ainize status`가 개수를 셉니다. 이 상태라면 아래 어느 명령도 아무것도 찾지 못합니다.

**먼저 사야 합니다.** 파일을 갖고 있다는 것은 사용 권한이 아닙니다 — 검증 노드는 채점한 지식을 전부 내려받지만
그중 어느 것 위에도 가르칠 수 없습니다. `ainize patch get <id>`가 둘 중 어느 쪽인지 알려 주고, 한 줄이면 해결됩니다.

```bash
ainize use krx-all-2761 --no-apply     # 가격 제시 → 확인 → 결제 → 내려받기, 모델에 올리지는 않음
```

## 1. 무엇에 더할지 찾기

```bash
ainize patch ls --q ticker --status LISTED
ainize patch tree krx-all-2761              # 무엇 위에 만들어졌고, 무엇이 그 위에 만들어졌고, 각자 무엇을 더했는지
ainize patch missing krx-all-2761           # 사람들이 이 노드에서 물었는데 답하지 못한 질문들
```

무엇을 써야 할지 알려 주는 것은 `patch missing`입니다. 이 노드가 지켜본, 그 지식이 답하지 못한 질문 목록이고, 각
질문을 몇 명이 물었는지가 함께 나옵니다.

## 2. 그 질문들을 가져오기

```bash
ainize dataset get krx-all-2761 --manifest          # 라이선스, 공개 범위, 행의 출처, 개인정보 점검
ainize dataset get krx-all-2761 -o questions.jsonl  # 그 지식이 실제로 배운 바로 그 바이트
```

공개한 사람이 학습 질문을 누가 읽을 수 있는지 고르고, 그 답은 기록에 남아 있습니다.

| 공개 범위 | 질문을 내려받을 수 있는 사람 |
| --- | --- |
| `public` | 누구나 |
| `derivative` | 이 지식 위에 만든다고 선언한 사람: CLI가 서명된 파생 의사(derive intent)를 보내고, 방금 동의한 조건을 출력하며, 그 선언은 기반 지식 쪽에 집계됩니다 |
| `private` | 아무도 — 잘린 파일을 주는 대신 그렇게 말합니다 |

`private`인 학습 세트라도 그 지식 위에 만드는 것 자체를 막지는 않습니다. 그 질문에서 출발하는 것만 막습니다. 내
질문을 직접 쓰고, 아래의 `--on`을 똑같이 쓰면 됩니다.

## 3. 그 위에 내 것을 가르치기

`questions.jsonl`에 내 행을 더하고 — 한 줄에 `{"prompt": …, "answer": …}` 하나 — 훈련합니다.

```bash
ainize teach train questions.jsonl --on krx-all-2761 --wait
```

`--on`이 이것을 별개의 지식이 아니라 파생물로 만듭니다.

- 기반의 질문이 **이미 아는 답**으로 유지되어, 내 수업이 그중 무엇을 망가뜨렸는지 점검에서 보입니다
  (`--no-inherit`은 기반의 질문을 유지하지 않고 기반에 대한 점검만 합니다);
- 기반이 "무엇 위에 훈련했는지"로 내 anchor에 정확한 테이블 상태와 함께 기록됩니다 — 그래서 내 지식을 사는 사람은
  둘 다 가격을 안내받고, 내 파일은 기반이 밑에 없으면 올라가기를 거부합니다;
- 기반의 답과 어긋나는 내 답은 `--yes-change`로 의도라고 말하기 전까지 거부됩니다.

`--wait`는 수업을 끝까지 따라가고 결과를 종료 코드로 냅니다. `0` 완료, `4` 붙지 않음, `5` 실패, `6` 운영자가 거절,
`7` 아직 진행 중, `8` 완료되었지만 라이브 모델에서 측정되지 않음.

## 4. 공개하기

```bash
ainize teach publish <job-id> --name "KRX tickers + biotech" --price 10 \
  --license CC-BY-4.0 --consent-permanent --consent-rights
```

두 개의 동의 플래그는 공개하는 사람의 것이고 기본값이 없습니다. 앞의 것은 이 기록이 영구적임을 이해했다는 뜻이고,
뒤의 것은 이 질문들을 공유할 권리가 있다는 뜻입니다. 자동 공개 노드에서는 바로 공개(announce)되고, 검토를 먼저
하는 노드에서는 운영자가 동의할 때까지 `PENDING_REVIEW`로 기다립니다(`ainize teach status <node url>`가 이 노드가
둘 중 어느 쪽인지 알려 줍니다). 공개된 뒤에는 다른 노드들이 검증해야 — 기본값 둘, `verifier.quorum` — LISTED가
되어 팔릴 수 있고, `ainize patch get <id>`가 어디까지 진행됐는지 보여 줍니다.

## 내 지식이 한 번 팔리면 누구에게 얼마가 가는가

분배는 **내 anchor**에서 읽습니다 — 공개할 때 적힌 약속이고, 파는 노드의 설정이 아닙니다 — 그리고 네트워크가
계보 30 %, 검증 5 %를 하한으로 강제합니다. 바깥 조상이 하나이고 검증 두 건이 집계된 지식을 10 크레딧에 판 경우:

```text
10.00   판매액
-3.00   계보 몫: 30 %를, 나를 제외한 조상 저자들에게 균등 분배
        (여기서는 저자 한 명 → 3.00. 내 예전 판본들이 줄줄이 있어도 바깥 저자의 몫은 희석되지 않습니다)
 7.00   내 쪽
-0.35   검증: 내 쪽의 5 %를 집계된 검증 노드 둘이 나눠 가짐 (각 0.175)
 6.65   내가 갖는 몫
```

기반을 만든 사람이 그 anchor에 데이터 제공자를 올려 두었다면, 그 사람은 기반의 3.00 안에서 그 anchor에 적힌 몫만큼
받습니다. 내 지식에 올라간 데이터 제공자 — 가르친 사람 본인이거나,
`ainize publish --contributor <addr>:<name>:<share>`로 지정한 주소 — 는 내 6.65에서 받습니다.

## 라이선스 규칙 두 가지

- 내 학습 세트의 라이선스는 `CC0-1.0`, `CC-BY-4.0`, `CC-BY-SA-4.0`, `ODC-By-1.0`, `Proprietary` 중 하나여야 합니다.
- 기반이 `CC-BY-SA-4.0`이면 내 학습 세트도 `CC-BY-SA-4.0`이어야 하고, 공개 범위도 기반 이상으로 열려 있어야 합니다.
  아니면 공개 시점에 조용히가 아니라 그 문장으로 거부됩니다.

## 잘 안 될 때

| 보이는 것 | 뜻 |
| --- | --- |
| `unknown_knowledge` | 이 노드에 없는 id — 오타이거나, 이 노드가 본 적 없는 지식. 아무것도 업로드되지 않았습니다 |
| `knowledge_not_held` | 목록에는 있지만 파일이 이 노드에 없습니다: `ainize use <id> --no-apply` |
| `knowledge_not_licensed` | 이 노드가 검증했기 때문에 파일이 있는 것입니다. 검증은 사용 권한이 아닙니다 |
| `license_incompatible` | 기반이 CC-BY-SA-4.0인데 내 학습 세트가 아니거나, 덜 열려 있습니다 |
| `--wait`의 종료 코드 `4` | 수업이 붙지 않았습니다 — 답이 점검을 통과하지 못했습니다. `--effort thorough`로 다시 훈련하세요 |
